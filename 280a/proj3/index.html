The one idea: follow the velocity

A flow model is trained on straight lines from noise to images, xt = (1 − t) x0 + t x1, and learns the velocity x1 − x0. It only sees xt, so it learns the average velocity of every pair through that point, which is why sampling paths curve and I ask the model again at every small step.

xt = (1 − t) ε + t x1

the path, t = 0 noise, t = 1 picture

vθ(xt, t, c) ≈ x1 − ε

what the model predicts

xt+h = xt + h · v(xt, t)

how sampling follows it, h = 0.02

def interpolate(image, noise, t):
    x_t = (1-t)*noise + t*image
    return x_t

Part 1.3–1.4 · One-step denoising and the velocity

One step follows the predicted velocity straight to t = 1. At 0.25 everything lands in the right place but comes out smooth and painted, since a model trained on squared error predicts the average of every lake that fits; by 0.75 it is almost my photo.

A.2 · one step

(1 − t) vgt = x1 − xt

1.4 · error per pixel
def one_step_denoise(x, t, condition, predict_velocity):
    v = predict_velocity(x,t,condition)
    x_1 = x + (1-t)*v
    return x_1

1.4 · Predicted vs. true update. The noise cancels between the two updates, so the error map is just one step vs. my photo. It looks like a Laplacian: dark in the sky and the water, bright on edges and foliage, and it thins out as t grows.

@torch.inference_mode()
def velocity_diagnostics(x_t, t, clean_image, epsilon, condition, predict_velocity):
    x_1_hat = one_step_denoise(x_t, t, condition, predict_velocity)
    predicted_update = x_1_hat - x_t
    ground_truth_update = clean_image - x_t
    error_map = torch.sqrt(((predicted_update - ground_truth_update) ** 2).mean(dim=1))
    return predicted_update, ground_truth_update, error_map

All three error maps share one colour scale, from 0 (black) to 0.5 (pale yellow), about the 99th percentile of the errors. Scaling to the single largest error, 1.46, left the maps almost black.

Part 1.5–1.6 · Euler sampling, from my photo and from noise

Euler takes small steps of h = 0.02 and asks the model again each time, so it can commit to finer detail as the picture cleans up. From my photo at t = 0.5 that is 25 steps; from pure noise it makes a new image (1.6).

xt+h = xt + h · vθ(xt, t, c)

A.3 · one Euler step, h = 0.02
@torch.inference_mode()
def euler_sample(x_start, t_start, step_size, velocity):
    n = math.ceil((1 - t_start) / step_size - 1e-9)
    x, t = x_start, t_start
    states = [(t, x)]
    for i in range(1, n + 1):
        t_next = 1.0 if i == n else t_start + i * step_size
        x = x + (t_next - t) * velocity(x, t)
        t = t_next
        if i % 5 == 0 or i == n:
            states.append((t, x))
    return x, states

Part 2.1 · Classifier-free guidance

vcfg = vc + w (vc − vu)

A.4 · c = my prompt, u = the empty prompt

Guidance fixes that: each step uses two predictions, with and without my prompt, and pushes past the conditional one (w = 7, same noises as 1.6). Every sample becomes a clean studio portrait, even the jar, so I gain quality and lose diversity.

def cfg_velocity(x, t, condition, w, predict_velocity, null_condition=''):
    v_unconditional = predict_velocity(x,t,null_condition)
    v_conditional = predict_velocity(x,t,condition)
    return v_conditional + w*(v_conditional-v_unconditional)

def edit(image, noise, t_start, condition, predict_velocity, w=7, step_size=0.02):
    x = interpolate(image, noise, t_start)
    velocity = lambda x, t: cfg_velocity(x, t, condition, w, predict_velocity, null_condition)
    final, _ = euler_sample(x, t_start, step_size, velocity)
    return final

Part 3.3 · Visual anagrams

Visual anagrams come from arithmetic on velocities: at every step I average the guided velocity for the picture as it is and the guided velocity for the picture turned upside down, with a second prompt, turned back. Hover over or tap a picture to turn it.

v = ½ [ vcfg(xt, t, p1) + F( vcfg(F(xt), t, p2) ) ]

F turns the picture 180°
def visual_anagrams(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
    def velocity(x, t):
        v1 = cfg_velocity(x, t, condition_a, w, predict_velocity, null_condition)
        v2 = rotate180(cfg_velocity(rotate180(x), t, condition_b, w, predict_velocity, null_condition))
        return (v1 + v2) / 2
    final, _ = euler_sample(noise, 0, step_size, velocity)
    return final

Part 3.4 · Hybrid images

Taking inspiration from Project 2's hybrids, I make pictures that look different up close and from far away by adding the low-pass velocity of one prompt to the high-pass velocity of another, split by a Gaussian with σ = 16.

v = Gσ ∗ v1 + (v2 − Gσ ∗ v2)

low frequencies of prompt 1, high of prompt 2, σ = 16
def highpass(x, sigma=16.0):
    return x - lowpass(x, sigma)

def make_hybrids(noise, condition_a, condition_b, predict_velocity, w=7, step_size=0.02):
    def velocity(x, t):
        v1 = cfg_velocity(x, t, condition_a, w, predict_velocity, null_condition)
        v2 = cfg_velocity(x, t, condition_b, w, predict_velocity, null_condition)
        return lowpass(v1) + highpass(v2)
    final, _ = euler_sample(noise, 0, step_size, velocity)
    return final

Visual anagrams with other viewsBells & whistles

Different arithmetic gives more visual anagrams. A view has to be an exact pixel permutation, so that noise stays noise from every view and the model sees the inputs it was trained on. I used a 90° rotation and an inner-circle rotation, which turns only a central disc. The owl is my favourite: only the centre changes and the ring stays put, purely from arithmetic on velocities.

v = ¹⁄N Σi Vi−1 vcfg(Vi xt, t, pi)

each view V a pixel permutation
def multiview_anagram(noise, conditions, views, w=7, step_size=0.02):
    def velocity(x, t):
        vs = [inv(cfg_velocity(f(x), t, c, w, predict_velocity, null_condition))
              for (f, inv), c in zip(views, conditions)]
        return sum(vs) / len(vs)
    final, _ = euler_sample(noise, 0, step_size, velocity)
    return final

Part B 1.1–1.2 · A one-step denoiser

A UNet (D = 128) sees a digit with Gaussian noise added and is trained with squared error to give back the clean digit. σ is fixed at 0.5 during training.

z = x + σ ε

1.2 · noising, ε ~ N(0, I)

L = ‖ Dθ(z) − x ‖²

1.2 · the denoiser's loss
def forward(self, x):                                 # UnconditionalUNet
    h1 = self.conv_in(x)                              # D, 28
    h2 = self.down1(h1)                               # D, 14
    h3 = self.down2(h2)                               # 2D, 7
    h4 = self.unflatten(self.flatten(h3))             # 2D, 7
    h5 = self.up1(torch.cat([h4, h3], dim=1))         # D, 14
    h6 = self.up2(torch.cat([h5, h2], dim=1))         # D, 28
    h7 = self.conv_out(torch.cat([h6, h1], dim=1))    # D, 28
    return self.final(h7)

1.2.0 · Noising. Ten test digits with the same noise sample, scaled by σ. They stay easy to read up to 0.5; by 1.0 the noise is as bright as the strokes.

1.2.2 · Other noise levels. The denoiser only ever saw σ = 0.5. Below it, it is close to an identity: σ = 0 comes back untouched. Above it, it starts to guess. At 0.8 stray stroke fragments appear, and at 1.0 it draws strokes that look like handwriting but not always the right digit: the 4 becomes a pair of brackets and the 9 a tangle.

1.2.3 · Denoising pure noise. All ten outputs are the same blurry overlay of every digit, a 0 with an 8 and a 9 inside. The squared-error denoiser outputs a weighted average of the training digits, weighting each by how likely it is to have produced the input. At small σ the input is close to one digit, so that digit gets almost all the weight. Pure noise is the limit of large σ: the input says nothing about the digit, so every training digit gets the same weight and the output is their mean. It matches the actual mean of the 60,000 training digits to within 0.02 RMS, and the loss levels off at 0.068, the training digits' variance around that mean.

Part B 2.1–2.3 · Flow matching with time

Flow matching turns the denoiser into a generator. A digit x1 and noise x0 are joined by a straight line, and the UNet (now D = 64) learns the velocity along it from xt and t. Time enters through two small fully connected blocks whose outputs scale the features after unflatten and after up1.

xt = (1 − t) x0 + t x1

2.2 · the path, x₀ ~ N(0, I), t ~ U(0, 1)

L = ‖ (x1 − x0) − uθ(xt, t) ‖²

2.2 · flow-matching loss

t1 · unflatten, t2 · up1

2.1 · features scaled by t₁, t₂ = FCBlocks(t)

xt+h = xt + h · uθ(xt, t)

2.3 · Euler sampling, h = 1/50
def time_fm_forward(unet, x_1, num_ts):
    t = torch.rand(x_1.shape[0], device=x_1.device)          # t ~ Uniform(0, 1), shape (N,)
    x_0 = torch.randn_like(x_1)                              # x_0 ~ N(0, I)
    t_ = t[:, None, None, None]                              # broadcast over C, H, W
    x_t = (1 - t_) * x_0 + t_ * x_1
    return F.mse_loss(unet(x_t, t), x_1 - x_0)

def time_fm_sample(unet, img_wh, num_ts, seed=0):
    torch.manual_seed(seed)
    x = torch.randn(1, 1, *img_wh, device=param_device)      # x_0 ~ N(0, I)
    step = 1.0 / num_ts
    for i in range(num_ts):
        t = torch.full((x.shape[0],), i * step, device=param_device)
        x = x + step * unet(x, t)
    return x

2.2 · Training. Ten epochs, batch 64, Adam starting at 10−2 and decaying exponentially to about 10−3. The loss falls fast and levels off near 0.09. Unlike the denoiser's it can never reach zero, because one xt lies on paths to many different digits.

Part B 2.4–2.6 · Class conditioning and guidance

The class goes in as a one-hot vector through two more FC blocks: the class scales the features and time shifts them. 10% of the time the vector is zeroed, so the same network also learns the unconditional velocity, and I can sample with classifier-free guidance at γ = 5. A better time-only modelBells & whistles

The time-only samples were the weakest result of Part B, about one in four a scribble. To measure progress rather than squint at grids, I score 1,000 samples per setting with a small MNIST classifier: the share it labels with over 90% confidence, and how evenly the ten digits appear (1 means all equally often). Real test digits score 94%.

The obvious fixes did little. 300 Euler steps instead of 50 change nothing, since the learned paths are nearly straight. Twenty more epochs at a constant 10−3 help a little, from 73% to 79%. Doubling the width to D = 128 under the same schedule came out no better, if anything noisier.

Autoguidance. Like CFG in Part A, but in place of the unconditional prediction I use the same model with weights from an earlier epoch (epoch 5), and amplify the velocity in the direction of the later one (epoch 30), following Karras et al. (2024). It takes the time-only model from 79% to 93% confident digits at w = 2, with no extra training.

v = vgood + w ( vgood − vbad )

good = epoch 30, bad = epoch 5
@torch.inference_mode()
def autoguided_sample(good, bad, w, img_wh=(28, 28), num_ts=300, seeds=range(40)):
    ...                                   # x: the same noise per seed as time_fm_sample
    h = 1.0 / num_ts
    for i in range(num_ts):
        t = torch.full((x.shape[0],), i * h, device=device)
        v = good(x, t)
        if w:
            v = v + w * (v - bad(x, t))
        x = x + h * v
    return x

What I learned
