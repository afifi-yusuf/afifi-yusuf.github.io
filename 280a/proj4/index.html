Part A.2 · Recover the homographies

w[x′ y′ 1]ᵀ = H[x y 1]ᵀ

With h33 = 1, each point gives two linear equations:

xh11 + yh12 + h13 − xx′h31 − yx′h32 = x′

xh21 + yh22 + h23 − xy′h31 − yy′h32 = y′

H has 8 unknowns and each point gives 2 equations, so 4 points are enough. I click 6–10 per pair so that one bad click doesn't throw it off, and solve the 2n×8 system Ah = b by least squares. I normalize the points first so the columns of A are on the same scale.

def computeH(im1_pts, im2_pts, normalize=True):
    p = np.asarray(im1_pts, np.float64)
    q = np.asarray(im2_pts, np.float64)
    T1 = _normalizer(p) if normalize else np.eye(3)
    T2 = _normalizer(q) if normalize else np.eye(3)
    A, b = homography_system(apply_h(T1, p), apply_h(T2, q))
    h = np.linalg.lstsq(A, b, rcond=None)[0]
    H = np.linalg.inv(T2) @ np.append(h, 1).reshape(3, 3) @ T1
    return H / H[2, 2]

I picked sharp points that don't move, spread over the whole overlap: roof trusses, pitch lines, rocks, the shoreline. No water, clouds, people or screens.

Part A.3 · Warp the images and rectify

For every output pixel, H−1 says where it comes from in the photo, and I sample the photo there. The output box comes from the warped corners, and an alpha mask marks the pixels that land inside the photo.

def sample_nearest(im, xs, ys):
    c, r = np.floor(xs + 0.5).astype(int), np.floor(ys + 0.5).astype(int)
    ...                                        # the closest pixel centre

def sample_bilinear(im, xs, ys):
    x0, y0 = np.floor(xs).astype(int), np.floor(ys).astype(int)
    fx, fy = xs - x0, ys - y0
    top = (1 - fx) * im[y0, x0] + fx * im[y0, x0 + 1]
    bot = (1 - fx) * im[y0 + 1, x0] + fx * im[y0 + 1, x0 + 1]
    return (1 - fy) * top + fy * bot           # the four closest, by distance

As a check, both match OpenCV's warpPerspective on all but 0.01% of pixels.

Rectification. I click the corners of something flat and send them to a rectangle with its real proportions, which I measured.

Part A.4 · Blend the images into a mosaic

The middle frame is the reference. I warp the other frames into it with their H (frame 4 uses the inverse of H3→4) onto one canvas big enough for all of them, then blend. Each pixel is weighted by its distance to the edge of its own frame.

Overwrite just pastes frames on top of each other. Feather takes the weighted average. Two-band averages only the blurred image (σ = 8 px) and takes the fine detail from one frame, so anything that moved doesn't show up twice.

Part A.5 · Cylindrical projection Bells & whistles · 280A

θ = u / f

x = f tan θ, y = v / cos θ

A pixel (u, v) on the cylinder lands at (x, y) on the middle frame's image plane.

Each pixel on the cylinder is a direction. I turn it into a point on the middle frame's image plane, then use H−1 to look it up in each original photo, and blend as before.

Focal length. The cylinder needs the focal length f. When the camera only turns, H = KRK−1, so I search for the f that makes my homographies closest to pure rotations: 1225 px, or 22 mm in 35 mm terms, close to the phone's 24 mm.

Straightening. I held the phone tilted about 6°, so the horizon came out curved. I find the axis I turned around from the same rotations and rotate the view so that axis points straight up.

Part B.1 · Find corners

Part B finds the points automatically. I follow the MOPS paper at a single scale, without rotation.

I run the course's harris.py on a 1024 px copy of each frame. On Hraunfossar frame 3 it finds 18,363 corners.

The 500 strongest bunch up on the waterfalls and the lava edge, so I use ANMS instead. Each corner gets the distance to the nearest corner that is clearly stronger (fi < 0.9 fj), and I keep the 500 with the largest distance. They spread over the whole frame.

def anms(xy, f, n=500, c=0.9):
    order = np.argsort(-f)                       # strongest first
    xy, f = xy[order], f[order]
    r = np.full(len(f), np.inf)
    for s in range(0, len(f), 1024):             # only stronger corners suppress
        e = min(s + 1024, len(f))
        d = ((xy[s:e, None] - xy[None, :e]) ** 2).sum(-1)
        d[f[s:e, None] >= c * f[None, :e]] = np.inf
        r[s:e] = np.sqrt(d.min(1))
    return order[np.argsort(-r)[:n]]

Part B.2 · Describe each corner

For each corner I blur the 40×40 window around it and sample it every 5 px into an 8×8 patch. Then I subtract the mean and divide by the standard deviation, so brightness and contrast don't matter.

blur = gaussian_filter(gray, 2.5)
off = (np.arange(8) - 3.5) * 5                 # 8 samples, 5 px apart, across 40 px
ox, oy = np.meshgrid(off, off)
d = sample_bilinear(blur, x + ox, y + oy)[0].reshape(-1)
d = (d - d.mean()) / d.std()

0.5ratio threshold

Part B.3 · Match the patches

For each patch I find the closest and second-closest patch in the other frame. A real match is much closer than the runner-up, so I keep it only if the ratio of their squared distances is under 0.5. That's the cutoff the paper's figure 6b suggests.

I made the same plot for my frames, using the final H to tell right matches from wrong ones. At 0.5 it keeps 85% of the right ones and 2% of the wrong ones.

Part B.4 · RANSAC and automatic mosaics

Some wrong matches still get through, like fans who moved. RANSAC picks 4 matches at random, fits H to them, and counts how many matches land within 10 px of their partner. I keep the largest set and refit H to it with computeH.

def ransac(p, q, eps=10.0, iters=2000):
    best = np.zeros(len(p), bool)
    for _ in range(iters):
        k = rng.choice(len(p), 4, replace=False)
        H = computeH(p[k], q[k])
        inl = reprojection_error(H, p, q) < eps
        if inl.sum() > best.sum():
            best = inl
    return computeH(p[best], q[best]), best

My clicks were bunched in the middle of each overlap, so my H is less accurate away from them: up to 20 px off on the RANSAC inliers. The automatic H is only 2–6 px off on my clicks.

I shuffled every frame I had into one pile: the three Part A videos, a fourth from Egypt vs Argentina in Atlanta, and the painting and rug from A.3. Atlanta looks a lot like Dallas, so it's a good test.

The program matches all 300 pairs. A pair counts if RANSAC keeps more than 8 + 0.3n of its n matches (from Brown and Lowe). Frames linked by passing pairs form a panorama, and each one goes on a cylinder like in A.5.
