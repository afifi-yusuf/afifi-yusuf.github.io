Part A.2 · Recover the homographies

w[x′ y′ 1]ᵀ = H[x y 1]ᵀ

With h33 = 1, each point gives two linear equations:

xh11 + yh12 + h13 − xx′h31 − yx′h32 = x′

xh21 + yh22 + h23 − xy′h31 − yy′h32 = y′

H has 8 unknowns and each point gives 2 equations, so 4 points are enough. I click 6–10 per pair so that one bad click doesn't throw it off, and solve the 2n×8 system Ah = b by least squares. I normalize the points first so the columns of A are on the same scale.

def computeH(im1_pts, im2_pts, normalize=True):
    p = np.asarray(im1_pts, np.float64)
    q = np.asarray(im2_pts, np.float64)
    T1 = _normalizer(p) if normalize else np.eye(3)
    T2 = _normalizer(q) if normalize else np.eye(3)
    A, b = homography_system(apply_h(T1, p), apply_h(T2, q))
    h = np.linalg.lstsq(A, b, rcond=None)[0]
    H = np.linalg.inv(T2) @ np.append(h, 1).reshape(3, 3) @ T1
    return H / H[2, 2]

I picked sharp points that don't move, spread over the whole overlap: roof trusses, pitch lines, rocks, the shoreline. No water, clouds, people or screens.

Part A.3 · Warp the images and rectify

For every output pixel, H−1 says where it comes from in the photo, and I sample the photo there. The output box comes from the warped corners, and an alpha mask marks the pixels that land inside the photo.

    ...                                        # the closest pixel centre

def sample_bilinear(im, xs, ys):
    x0, y0 = np.floor(xs).astype(int), np.floor(ys).astype(int)
    fx, fy = xs - x0, ys - y0
    top = (1 - fx) * im[y0, x0] + fx * im[y0, x0 + 1]
    bot = (1 - fx) * im[y0 + 1, x0] + fx * im[y0 + 1, x0 + 1]
    return (1 - fy) * top + fy * bot           # the four closest, by distance

As a check, both match OpenCV's warpPerspective on all but 0.01% of pixels.

Rectification. I click the corners of something flat and send them to a rectangle with its real proportions, which I measured.

The close-ups are the signature and the rug border rectified 6× larger. Nearest neighbour gives blocky, jagged edges; bilinear is smooth. Bilinear is about 3× slower since it reads four pixels instead of one, but it's still a fraction of a second, so I use it everywhere else.

Part A.4 · Blend the images into a mosaic

The middle frame is the reference. I warp the other frames into it with their H (frame 4 uses the inverse of H3→4) onto one canvas big enough for all of them, then blend. Each pixel is weighted by its distance to the edge of its own frame.

Overwrite just pastes frames on top of each other. Feather takes the weighted average. Two-band averages only the blurred image (σ = 8 px) and takes the fine detail from one frame, so anything that moved doesn't show up twice.

Part A.5 · Cylindrical projection Bells & whistles · 280A

θ = u / f

x = f tan θ, y = v / cos θ

A pixel (u, v) on the cylinder lands at (x, y) on the middle frame's image plane.

Each pixel on the cylinder is a direction. I turn it into a point on the middle frame's image plane, then use H−1 to look it up in each original photo, and blend as before.

Focal length. The cylinder needs the focal length f. When the camera only turns, H = KRK−1, so I search for the f that makes my homographies closest to pure rotations: 1225 px, or 22 mm in 35 mm terms, close to the phone's 24 mm.

Straightening. I held the phone tilted about 6°, so the horizon came out curved. I find the axis I turned around from the same rotations and rotate the view so that axis points straight up.
